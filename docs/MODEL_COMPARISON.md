# Local model comparison: phi4-mini vs llama3.2:3b

DocuMind falls back to a **local model running in Ollama** when Gemini is unavailable: offline, overloaded (503), or out of quota (429). Without a Gemini key, the local model is the only one. This page compares the two local models we tried, on exactly the jobs DocuMind gives them.

**Current choice: `llama3.2:3b`** (set with `OLLAMA_MODEL=llama3.2:3b` in `backend/.env`).

## The two models

| | **phi4-mini** | **llama3.2:3b** |
|---|---|---|
| Made by | Microsoft | Meta |
| Parameters | 3.8 billion | 3.2 billion |
| Download (Ollama default, 4-bit Q4_K_M) | ~2.5 GB | ~2.0 GB |
| Context window | up to 128K tokens | up to 128K tokens |
| Licence | MIT | Llama 3.2 Community License |
| Officially supported languages | English-first | English, German, French, Italian, Portuguese, **Hindi**, Spanish, Thai |
| Known for | Reasoning and maths for its size | Natural English, predictable behaviour, multilingual |
| Ollama tag | `phi4-mini` | `llama3.2:3b` |

## What each model has to do in DocuMind

1. **Query rewriting** (`app/query.py`): turn Hindi or Hinglish questions, and follow-ups like "and for interns?", into one standalone English search query. If this goes wrong, search finds the wrong documents and everything after it fails.
2. **Grounded answering** (`app/rag.py`): answer only from the retrieved sources, cite them as `[n]`, refuse with "I couldn't find this in your documents." when the answer isn't there, ignore instructions hidden inside documents, and reply in the user's language.

## First test: Hindi/Hinglish translation (17 Oct 2026)

Same few-shot rewriting prompt, same laptop CPU, run with `backend/eval/compare_local_models.py`:

| Question | phi4-mini | llama3.2:3b |
|---|---|---|
| मुझे एक साल में कितने दिन की छुट्टी मिलती है? | ✗ "How many days have I missed working this year?" | ✓ "How many days of leave are given in a year?" |
| क्या इंटर्न को भी छुट्टी मिलती है? | ✗ "Is there a meeting between the interior and the exterior?" | ✓ "Do interns also get leave?" |
| mujhe sick leave ke liye doctor certificate kab chahiye? | ~ "What is the doctor's certificate required for sick leave?" | ✓ "When do I need to get a doctor's certificate for sick leave?" |
| Score | **0.5 / 3** | **3 / 3** |
| Time per translation (warm) | 1.1–1.5 s | 1.1–1.6 s |
| First call (includes loading the model) | 26.6 s | 43.5 s |

**What happened in the app:** with phi4-mini, the Hindi leave question was rewritten as *"How to merge multiple PDF files into a single PDF using Adobe Acrobat?"*. Search then returned unrelated sources, and the model (correctly) said it couldn't find an answer. With a wrong search query, even a perfect answering model cannot recover. That is why translation quality decided the choice.

## Full comparison (all aspects)

The measured section below is generated by the comparison script; the verdict after it adds a manual review. It runs every model through the same tests: translation, follow-ups, English answers with citations, a Hindi answer, refusals, the prompt-injection document, speed and memory. Re-run it after changing models or prompts.

**Run it** from the project folder, with Ollama running and both models pulled. It takes about 5–10 minutes on a CPU.

cmd:

```
docker compose run --rm -v "%cd%\backend\eval:/app/eval" -v "%cd%\sample_docs:/sample_docs" -v "%cd%\docs:/app/docs" backend python -m eval.compare_local_models phi4-mini llama3.2:3b
```

PowerShell: the same command, with `${PWD}` instead of `%cd%`.

## Verdict (from the full run on 17 Oct 2026)

| Aspect | phi4-mini | llama3.2:3b | Winner |
|---|---|---|---|

| Refuses out-of-scope questions | 2/3: answered "India won the 2011 Cricket World Cup" from its own knowledge | **3/3** | **llama3.2:3b** |

| Licence | MIT | Llama 3.2 Community License | phi4-mini (simpler) |

**Decision: `llama3.2:3b`.** It is smaller, uses less memory and is equally fast. It is equally accurate on English questions. It is clearly better on the three things that matter most for DocuMind's users:

1. **Understanding Hindi and Hinglish** (6/6 vs 2/6). If the search query is wrong, nothing after it can be right.
2. **Replying in the user's language.**
3. **Staying grounded.** phi4-mini answered an out-of-scope cricket question from its own memory instead of refusing, which is exactly the hallucination a RAG system must avoid.

phi4-mini's only edge is citing a little more consistently (6/6 vs 5/6). That's worth watching, but not decisive.

**Notes on the numbers**

- The script scores translations by keywords, which can be generous; the table above adds a manual review of every output.
- Answer time is about 11 s on this laptop's CPU. Most of it is the model reading the 5 retrieved sources (around 2,000 tokens) before writing. Gemini answers in about 2 s, which is why the local model is the fallback, not the default.
- Out-of-scope questions are a small sample (3). Run the script again after any prompt change.
- **Next candidate** if more quality is needed: `qwen3.5:4b` (~3.4 GB), compared with the same script.

## How to talk about this in an interview

- **We chose with data, not hype.** I built a small benchmark with the real prompts and real documents, ran both models, and kept the results in the repository.
- **Test the weakest link.** In RAG, the rewriting and retrieval step fails silently. A fluent answer to the wrong search is still wrong, so we measured translation separately from answering.
- **The fallback design makes swapping cheap.** Changing models is one setting (`OLLAMA_MODEL`), because the LLM sits behind LangChain's common chat-model interface.
